# Codex Usage Lens

在 Codex 每轮回复下方显示精简的用量按钮，点击查看本轮明细和会话累计。
独立开发，MIT 开源；支持可选的会话用量浮窗。

![用量按钮和明细弹层，数据来自合成演示](assets/preview.png)

## 从插件市场安装

打开 Codex 的「插件 → 添加插件市场」，填入：

```text
https://github.com/LoveYouEndless/codex-usage-lens
```

1. 安装并开启 **Codex Usage Lens**。
2. 在 Codex 中审阅插件 hooks，由你确认是否信任。
3. 正常新建、恢复会话或发送消息，助手会自动准备并恢复；已有可用连接时显示用量按钮。

正常使用不需要终端命令，也不需要为 Lens 配置 API Key。默认不创建额外快捷方式
或登录启动项。

首次没有出现按钮，或需要从停止状态恢复时，在会话中选择 `@Codex Usage Lens` 并发送：

```text
@Codex Usage Lens 启动用量监控。
```

如果提示「已准备一次重启」，先完成当前任务，再于 15 分钟内**完全退出 Codex**，
等待助手自动重新打开一次。之后按平常方式使用即可。

重启后的自动恢复范围及不同启动入口的区别见下文。

## 重启与升级

自动恢复以用户已信任 hooks 为前提，Lens 不写入信任记录，也不代替用户确认。
Windows 下，`SessionStart` 负责会话启动和恢复，`UserPromptSubmit` 负责发送消息时兜底。
两者异步运行并复用同一助手。只打开应用浏览历史时，不保证会话 hook 已触发。
CLI 版本暂不纳入支持范围。

| 桌面启动方式 | 信任 hooks 后的行为 |
| --- | --- |
| Codex++，API Key 或官方登录 | 自动恢复助手；有可用 CDP 连接时显示按钮，探测启动器记录的实际端口 |
| CC Switch 配置后启动 | 自动恢复助手；有连接时显示，没有连接时等待 |
| 直接启动 Codex | 自动恢复助手；普通启动缺少连接时等待 |

hooks 不会自动安排重开。缺少连接时，显式启动可以准备一次重开；它不会永久改变
普通入口的启动参数。停止监控、关闭插件、等待超时或检测到用户已经手动重开，
都会取消尚未执行的重开请求。

| 场景 | 实际行为 |
| --- | --- |
| 信任 hooks 后新建/恢复会话或发送消息 | 首次部署或升级助手；后续复用已有助手 |
| hook 触发但缺少连接 | 助手等待，不自动安排重开 |
| 显式启用时缺少连接 | 等待用户在 15 分钟内完全退出，然后自动重新打开一次 |
| 界面重载或具备连接的重启 | 运行中的助手自动重新连接 |
| 完整退出后普通启动 | 会话 hook 自动恢复助手；无连接时仍需显式准备重开 |
| 重启电脑 | 下次会话 hook 自动恢复未暂停的助手 |
| 停止监控 | 持久暂停，取消尚未执行的重开、撤下统计并退出助手；hooks 不会重新唤起 |
| 等待重开超时 | 只取消这次重新打开；助手继续等待可用连接 |
| 配置中的 `enabled = false` | 撤下统计并退出助手，不修改配置文件 |
| 客户端升级 | 启动器重新查找已安装客户端，避免快捷方式绑定旧版本路径 |
| 界面不兼容 | 暂停对该窗口的注入，等待后续 Lens 更新 |

沿用 Codex 原有开关：

```toml
[plugins."codex-usage-lens@codex-usage-lens"]
enabled = true
```

改为 `false` 后，助手在下一次检查时撤下统计并退出；移除插件条目也会退出。
配置临时无法解析时暂停统计，不把配置内容写入日志。重新开启后，
下次受信任的 hook 可恢复助手；若已执行过停止监控，需显式启动解除暂停。
登录恢复和专用快捷方式保留为明确选择的高级功能，不是默认流程；
登录恢复本身无法让普通启动的客户端自动获得所需连接。

### 可选的后台等待

助手运行时本来就会持续检测可用连接；Codex 尚未打开时等待，连接出现后自动
挂载按钮。检测到 Codex 进程不等于已具备注入连接，单独增加进程监控或注册
服务不能解决这个限制。

如需让助手在重启电脑后继续等待，可自行选择「登录后恢复助手」。
它只恢复后台助手，**不会自动打开或重启 Codex**，也不注册 Windows 服务。
普通启动缺少连接时仍需在会话中 `@Codex Usage Lens` 启用并按提示重新打开；
不能把这个选项理解为保证每次开机后按钮都自动显示。默认安装不注册登录启动项。

可在会话中明确要求「启用登录后恢复助手」或「关闭登录后恢复助手」，
由插件执行对应设置；也可使用下方高级命令自行配置。

Lens 与 Codex 独立运行。Node 缺失、配置不可用或连接端口被占用时，启动器
改用普通启动；调试启动报错或客户端立即退出时，只尝试一次普通启动。
不会强行关闭客户端，也不会修改安装包。不能保证未来所有版本都兼容，
正常 Codex 启动入口始终可直接使用。Lens 更新后，下次受信任的 hook
或显式启用会部署新版；hook 定义变化时需由用户重新审阅并信任。
一次性重新打开完成不等于已验证按钮可见；客户端不兼容时仍会暂停统计。

## 使用

- 点击「分支到新聊天」右侧的「用量」查看明细，窄窗口放不下时自动使用独立行。
  按 Escape 或点击外部关闭。
- 用量按钮默认无边框，悬停或展开时显示浅色背景，文字颜色跟随原生操作按钮。
  历史回复中跟随操作栏隐藏，鼠标进入回复区域或键盘聚焦时显示；详情展开期间保持可见。
- 支持自动单位、原值、K、M，保留单位选择。
- 在明细中勾选「显示会话浮窗」，可拖动浮窗位置。
- 会话浮窗的详情紧贴浮窗边缘，更新计数时保持展开。
- 对 Codex 说「停止 Codex Usage Lens」可移除界面并持久暂停；再次显式启动恢复。

界面根据客户端语言显示中文或英文。

## 统计口径

「本轮」按用户轮次汇总多次用量更新，包括工具操作引起的模型调用。
「计数更新」不是精确的 API 请求次数。重复出现的累计记录不会重复计数。

缓存输入包含在输入中，推理包含在输出中；明细不会把它们再次加到总量。
上下文显示最近一次记录的输入占用，不等于会话累计消耗。
这里的数字是 token 记录，不是订阅额度，也不用于估算账单。

恢复会话后，如果日志从历史累计值中途开始，第一笔只采用已记录的最近一次
用量，并标记「本轮记录不完整」。累计计数下降时，开始新的本地计数周期，
会话总量包含前后两个周期。缺失记录不能还原，部分轮次可能少计。
同一会话的多个日志按轮次 ID 合并，不会把各文件中的累计值直接相加。

## 兼容范围

自动 hooks 当前仅支持 Windows 桌面端，macOS/Linux 的 hook 为无操作入口。
需要支持并加载受信任插件 hooks 的 Codex 客户端；不以后台助手启动成功代替
客户端信任或按钮可见性的验证。支持能从本机日志找到的 UUID 会话，需要客户端
提供回复消息 ID 标记和回复操作区时间戳。不支持网页 ChatGPT，也不支持没有
本机日志的远程会话。目前连接一个主窗口，多窗口尚未覆盖。

按钮通过本地 Chrome DevTools Protocol 临时注入，不是官方原生底栏扩展。
客户端的界面结构或日志格式变化时，可能需要更新插件。
不确定消息归属时不显示按钮，不用其他会话的数据替代。

## 隐私和卸载

运行期间不向远端发送数据。只读本机日志，向本地界面传递计数、会话/轮次/
消息 ID、模型名和时间戳；hook 输入流直接丢弃，不解析、保留或记录用户消息，
也不把它用于拼接命令。不保留或传递对话正文，不写入会话日志和安装包。
调试端口应仅监听本机，不要开放或转发到网络。

卸载前对 Codex 说「卸载 Codex Usage Lens 的启动配置」，再移除插件。
它会停止助手并删除自己创建的桌面和登录快捷方式，保留状态目录供手动清理。
升级自 0.2.x 时，已有快捷方式和登录项会保留，不会静默删除；可用上述卸载操作
移除旧入口，再启用新版。新版默认不会重新创建它们。

本地状态默认保存在 `%LOCALAPPDATA%\CodexUsageLens`，不写入插件缓存目录。
`CODEX_HOME` 可指定日志主目录，命令行也支持 `--codex-home` 和 `--state-dir`。

## 高级设置与排查

需要 Node.js 22 及以上，启用时会寻找系统 Node 或 Codex 缓存的运行环境。
配置解析器已经随插件打包，不需要用户执行 `npm install`。
本地界面连接使用仅监听本机的 Chrome DevTools Protocol；自动恢复时探测
Codex++ 的 `latest-status.json`（支持 `CODEX_PLUS_STATE_DIR`）、Lens 已安装端口
以及 9229、9222、9230、9223。状态文件只作为端口线索，仍验证目标是 Codex 主界面。
明确指定 `-Port` 时只连接该端口。一次性重开会准备选定的连接。

```powershell
.\scripts\control.ps1 -Action Start
.\scripts\control.ps1 -Action Status
.\scripts\control.ps1 -Action Stop
.\scripts\control.ps1 -Action Uninstall
# 仅明确需要这些额外入口时：
.\scripts\control.ps1 -Action Setup -DesktopShortcut
.\scripts\control.ps1 -Action Setup -LoginRecovery
.\scripts\control.ps1 -Action DisableLoginRecovery
# 找不到客户端或需要指定端口时：
.\scripts\control.ps1 -Action Start -CodexPath "C:\实际路径\Codex.exe" -Port 9229
```

`Stop` 持久暂停当前助手并取消尚未执行的重新打开；hooks、登录恢复和
专用启动器不会解除暂停，显式 `Start` 才解除。以前明确配置的登录恢复入口保留，
可单独用 `DisableLoginRecovery` 关闭登录恢复，不影响当前监控；`Uninstall` 一并卸载启动入口。
运行代码在 `%LOCALAPPDATA%\CodexUsageLens\runtimes\<版本>`，启动入口在它的
父目录，不依赖插件缓存是否被清理。本地诊断文件为 `status.json`、
`launcher-status.json`、`restart-request.json`、`hook-status.json`（恢复失败时）和
`helper.log`；`paused` 文件保存停止状态。
